# ADR — isolated .NET 10 CRM SQL candidate host

Status: candidate implementation, NOT runtime promotion. Risk: HIGH (persistence/security boundary). Owner streams: CRM Backend, Database and QA, sequenced in `feature/crm-sql-centralization` / draft PR #252.

The existing .NET 8 CRM API cannot reference the new .NET 10 SQL adapters. Rather than silently upgrading the source runtime or duplicating endpoint implementations, `tools/CRM.Api.SqlCandidate` targets .NET 10 and links the existing API source, Application and Infrastructure. Two compile-conditional composition hooks in the shared Program are active ONLY in the candidate project. Native .NET 8 builds retain their current behavior and must pass regression tests.

The candidate requires explicit Development configuration, a tenant and an encrypted dedicated `CrmMigration_...` SQL connection with a non-SA SQL identity. It removes/replaces all 13 foundation store DI registrations with the reviewed SQL adapters. It never migrates, seeds or creates a database automatically; it never falls back to memory. Connection values are not logged. Certificate trust bypass is allowed only for the explicit loopback lab SQL endpoint. Actual DB permissions still require provisioning/review; a non-SA username alone is not proof of least privilege.

The candidate binds to loopback on an ephemeral port. Every HTTP surface except GET `/health` and GET `/health/live` returns sanitized 503/no-store. `/health/ready` deliberately returns 503: liveness is not acceptance or SQL readiness. Neither JWT/permissions nor Portal Audit is fabricated. API security/audit integration must reuse the existing Portal boundary before opening routes. No new login, permissions engine, audit engine, notifications or menu/configuration engine is created. Remaining non-store services and foundation UnitOfWork/readiness flags are not automatically productized by changing store DI.

This candidate is verified only against the reviewed main contracts. Dirty MarketingIndo source files and active in-memory service remain untouched. Live-state capture/reconciliation, complete typed snapshot import to business storage, reference/lifecycle consistency, Portal authorization/audit, image/release gates and controlled cutover remain mandatory. No container deployment or shared image parity is claimed by host build/tests.

Files owned: shared `src/CRM.Api/Program.cs` conditional hooks; `tools/CRM.Api.SqlCandidate`; `tools/CRM.Api.SqlCandidate.Tests`; this ADR and coordination checkpoint. Verification: Release build, DI replacement tests, unsafe-config rejection, HTTP blocking/liveness tests, coverage for the new composition code, existing .NET 8 Unit/Architecture regression. Tests use a clearly synthetic nonexistent SQL identity and do not open a SQL connection.
